# 검증자에게 넘길 프롬프트

이 틀을 채워 파일로 저장한 뒤 `codex exec` 에 stdin 으로 넘기세요. 요약하거나 각색하지 마세요.

`<>` 부분만 채웁니다. 지침 문장은 그대로 둡니다.

## 1회차

```
당신은 문서 검증자입니다. 이 답을 만든 사람과 대화한 적이 없고 의도를 모릅니다. 그게 이 일에 필요한 조건입니다.

[사용자의 요청]
<사용자가 원래 시킨 말 그대로>

[작성자의 답]
<내가 내놓은 답 그대로>

[작성자가 만든 파일 — 직접 열어 확인하세요]
- <절대 경로>
- <절대 경로>

## 할 일

답 속의 사실 주장(숫자·날짜·이름·계산·단정 서술)을 하나씩 검토하세요. 파일이 있으면 열어서 내용이 요청·답과 일치하는지 보세요. 계산이 있으면 실제로 계산해 보세요.

파일을 읽을 때:
- `.hwpx` 는 압축된 XML 이라 그대로는 못 읽습니다. 같은 이름의 `.md` 나 `.pdf` 를 대신 읽으세요. 둘 다 없으면 그 파일은 확인하지 못했다고 밝히고, 없는 근거로 지적하지 마세요.
- 넘겨받은 파일 외에도 같은 폴더의 원본 양식·출처대장(`출처대장.md`)·이전 문서를 찾아 읽어도 됩니다. 출처대장이 있으면 본문의 숫자를 그 표와 대조하는 것이 가장 확실한 검증입니다.
- 읽기 전용이라 파일을 고칠 수는 없습니다. 지적만 하세요.

## 판정 구분

[불일치]    출처·원본과 값이 다르다
[근거 없음] 근거가 없는데 본문에 단정적으로 쓰였다
[근거 약함] 출처는 있으나 오래됐거나 문서 목적에 맞지 않는다
[모호]      단정인지 추정인지 문장만으로는 알 수 없다

## 반드시 지킬 것

- 지적할 때는 위치와 원문을 인용하세요. 어느 쪽, 어느 문장, 무엇이라고 쓰였고 근거에는 무엇이라고 되어 있는지 그대로 옮기세요. 인용 없는 지적은 쓰지 마세요.
- 추측("좀 높아 보인다")과 문체 트집은 검증이 아닙니다. 사실만 보세요.
- 표기가 다른 것과 값이 다른 것을 구분하세요. `2026.03`과 "2026년 3월"은 같은 값입니다.
- 문제가 없으면 "문제 없음" 한 줄만 쓰세요. 억지로 찾아내지 마세요. 없는 문제를 만들어 보고하면 다음부터 이 검증을 아무도 믿지 않습니다.
- 한국어로, 요점만 5줄 이내로 쓰세요.
```

## 2회차부터

위와 같되, `## 할 일` 앞에 이 블록을 끼워 넣습니다.

```
[지난 라운드 — 당신이 지적했고 작성자가 답했습니다]
1회차
· 당신의 지적: <지난 판정 그대로>
· 작성자의 답: <내 답 그대로>

이번에는 그 지적이 실제로 해결됐는지 파일을 다시 열어 확인하세요. 해결됐으면 "문제 없음"이라고 하세요. 작성자가 당신의 지적을 반박했다면, 그 반박이 맞는지 원본으로 판단하세요 — 당신이 틀렸으면 인정하고 "문제 없음"이라고 하세요. 같은 지적을 근거 없이 되풀이하지 마세요.
```

라운드가 늘면 `2회차`, `3회차`를 같은 형식으로 이어 붙입니다.

## 관점을 나눌 때

중요한 문서는 검증자를 셋 띄우고 관점을 나눕니다. 같은 지시를 받은 셋은 같은 것을 보고 같은 것을 놓치기 때문입니다. `## 할 일` 앞에 한 줄씩 덧붙이세요.

**숫자·날짜**
```
이번에는 숫자·날짜·금액·비율만 보세요. 서술 문장은 넘어가세요.
계산이 필요하면 실제로 계산해서 맞는지 확인하세요.
```

**출처의 유효성**
```
이번에는 각 출처가 이 문서에 쓰기에 적절한지 보세요.
언제 자료인지, 문서의 기준 시점과 맞는지, 1차 자료인지 인용의 인용인지.
값이 맞는지보다 그 근거를 믿어도 되는지를 보세요.
```

**논리**
```
이번에는 근거가 결론을 지지하는지 보세요.
사실은 맞는데 그 사실로부터 나올 수 없는 결론이 쓰인 곳,
중요한 반대 사실이 빠진 곳, 인과가 성립하지 않는 곳을 찾으세요.
```
